  • Hierarchy. Epic (a PRD module) › story › task. In Jira these become Epic › Story › Sub-task.
  • Story IDs. User story items keep their US- ID from the user stories. PRD gap items (PG-) cover PRD requirements the surveys didn't ask about, such as sign-up and communities; they have "done when" checks until someone writes Given / When / Then scenarios for them. Enabling items (EN-) are setup and non-functional work from PRD sections 7 and 8.
  • Points are proposed, Fibonacci (1, 2, 3, 5, 8), and relative: a 5 is about the size of building one data model with its Prisma model and migration, REST endpoints, role guards, validation and tests. Re-estimate together in sprint planning. A story's points are the sum of its tasks.
  • Areas: api NestJS modules and REST routes (one Lambda behind the API Gateway HTTP API) · db PostgreSQL tables through Prisma migrations, and DynamoDB tables for chat, feed and connections · worker Lambda jobs on SQS, DynamoDB Streams and EventBridge Scheduler · mobile Flutter · web Next.js portal and admin panel · design · infra · qa tests and audits. Stack as in PRD section 8.
  • PRD version 5. The group accepted all twelve survey recommendations (R1–R12) on 15 October 2026, so their work is now in the stories it belongs to (see where the survey work went). The same version added the interactive 2D map (VM-08 to VM-15) to the Venue maps epic (+148 pts).
  • PRD version 6. The recommended stack is now serverless AWS Amplify Gen 2 in ap-south-1 (PRD section 8), so the tasks were rewritten for it: Amplify Data (GraphQL on AppSync, with subscriptions for live updates), DynamoDB with GSIs, Lambda jobs on SQS, DynamoDB Streams and EventBridge Scheduler, Cognito, Amplify Storage with CloudFront, Amazon SES and Amplify Hosting. New tasks cover access-pattern design, the custom SMS sender, dead-letter handling, the image resize Lambda and AWS account set-up; Cognito and conditional writes made some tasks smaller (+9 pts in all). That stack change made no requirement changes. PRD version 7 replaced this stack (below).
  • PRD version 6: payments and the map builder. Two team decisions on 15 October 2026 added requirements. EP-14 Sandbox payments (Should, 73 pts) covers HR-14 and HR-17 to HR-20: each payee connects their own PayHere sandbox account, organisers pay deposits and instalments, vendors pay stall fees, and cancellation fees and refunds follow the booking's terms; no real money moves. US-A03 gained a read-only payments panel (+3 pts, a Should part inside a Must story). The map builder (VM-16 to VM-22) adds US-O17 (Must), US-O18 (Should) and US-O19 (Could) to Venue maps. The canvas, the map record and phone editing used to sit in US-O10 and US-O15; they are now built once in US-O17, so those two stories shrank by 18 pts and nothing is counted twice (+50 pts net). See the research briefs for the sources.
  • PRD version 7 (20 November 2026). The stack now matches the team's code repo (PRD section 8): a Flutter app; the Next.js portal on Amplify Hosting; a NestJS API as one Lambda behind an API Gateway HTTP API, defined in AWS CDK in ap-south-1; Cognito sign-in as Amplify Gen 2 code; PostgreSQL through Prisma as the main database, with DynamoDB kept for chat messages, feed items and WebSocket connections; an API Gateway WebSocket API for live updates instead of AppSync subscriptions; FCM push instead of Expo Push; PostgreSQL full-text and trigram search (typo tolerance is back); and the PayHere notice as a plain REST route. 67 tasks were rewritten, 9 added (API stack fixes, Prisma in the Lambda bundle, deploys from CI, the shared PostgreSQL host, DynamoDB tables in CDK, the users table, the Firebase project, the WebSocket API and its publish helper) and 1 removed (the DynamoDB backfill script): +16 pts in all, mostly in EP-00; rank scores in PostgreSQL made PG-09 3 pts smaller. Changed and new tasks carry a v7 tag beside their ID. That stack change made no requirement changes. Jira was not updated; see Importing into Jira.

Importing into Jira

Imported on 22 October 2026 into the Tezera space (TES) on tezera.atlassian.net. Jira is now the live backlog: change estimates there, because importing this CSV again creates duplicates instead of updating items. The steps below are what worked.

  1. Click Download Jira CSV above, or use the snapshot research/tezera-work-items-jira.csv. It lists epics first, then stories, then sub-tasks, which is the order Jira needs to link them.
  2. Use Jira's classic CSV importer, which needs no admin rights: /secure/BulkCreateSetupPage!default.jspa?externalSystem=com.atlassian.jira.plugins.jim-plugin:bulkCreateCsv on the Jira site. The sidebar's "Import work" uses Rovo AI instead. Leave the date format at its default; the file has no dates.
  3. Map Issue ID to Issue ID and Parent to Parent: that rebuilds Epic › Story › Sub-task. Tick "Map field value" for Issue Type and map Sub-task to Subtask. Map Story Points to Story Points (team-managed spaces call it "Story point estimate"), and Labels to Labels. Skip Epic Name if the field isn't listed.
  4. The importer takes 250 rows per file and summaries of 255 characters at most. The TES import went in two parts: epics and stories first, then sub-tasks with Parent set to each story's Jira key (TES-223 to TES-317).
  5. Priority is mapped Must → High, Should → Medium, Could → Low, Later → Lowest; the MoSCoW value is also a label (moscow-must). The TES space has no Priority field, so there the labels are the only MoSCoW record. Every summary starts with its ID, such as [US-C01], so items can be traced back here.
  6. Jira boards count story points on stories, not sub-tasks. The sub-task points are there to show how the story total was reached.
