  • Hierarchy. Epic (a PRD module) › story › task. In Jira these become Epic › Story › Sub-task.
  • Story IDs. User story items keep their US- ID from the user stories. PRD gap items (PG-) cover PRD requirements the surveys didn't ask about, such as sign-up and communities; they have "done when" checks until someone writes Given / When / Then scenarios for them. Enabling items (EN-) are setup and non-functional work from PRD sections 7 and 8.
  • Points are proposed, Fibonacci (1, 2, 3, 5, 8), and relative: a 5 is about the size of building one CRUD endpoint set with validation and tests. Re-estimate together in sprint planning. A story's points are the sum of its tasks.
  • Areas: api NestJS module · db Prisma schema or SQL · worker BullMQ jobs · mobile React Native + Expo · web Next.js portal and admin panel · design · infra · qa tests and audits. Stack as in PRD section 8.
  • Not included: anything that only exists because of an unaccepted survey recommendation (R1–R12). It is sized separately under Waiting on a group decision so it can be added once the group decides.

Importing into Jira

  1. Click Download Jira CSV above, or use the snapshot research/tezera-work-items-jira.csv. It lists epics first, then stories, then sub-tasks, which is the order Jira needs to link them.
  2. In Jira, use the CSV importer from the external system import (needs Jira admin rights). Map Issue ID to Issue ID and Parent to Parent: that rebuilds Epic › Story › Sub-task. Map Story Points to Story Points (team-managed projects call it "Story point estimate"), and each Labels column to Labels.
  3. Priority is mapped Must → High, Should → Medium, Could → Low, Later → Lowest; the MoSCoW value is also a label (moscow-must). Every summary starts with its ID, such as [US-C01], so items can be traced back here.
  4. Jira boards count story points on stories, not sub-tasks. The sub-task points are there to show how the story total was reached.

Column names follow Atlassian's guide to keeping parent-child links in a CSV import; check them against your instance's import screen. Sources: user stories, personas, PRD version 4, architecture.
